# Hackathon submission

## Project

Agent-Native Web tests whether one shared runtime can replace task-specific screens and hard-coded business-action catalogs. Providers publish conversational “worlds”; a consumer states an intent; the platform discovers relevant worlds, generates a fresh interface, and passes any generated action through one typed `agent.invoke(...)` bridge. Identity, authorization, validation, persistence, transport, and execution boundaries remain deterministic.

The main contribution is therefore not “AI generated a page.” It is the combination of a generative interaction layer with a fixed, testable trust substrate and an evidence trail that separates demonstrated behavior from modeled assumptions.

## How to read the evidence

Every result below is labeled so unlike evidence is not conflated:

- **TESTED** — asserted by the deterministic repository test suite.
- **DOCUMENTED LIVE** — reported from an opt-in OpenRouter run and summarized in the repository. Raw run output is not checked in, so these results are self-reported and are not rerun by the default suite.
- **STRUCTURAL** — follows directly from the implementation or architecture.
- **MODELED** — calculated from stated assumptions rather than observed user behavior.

The “baseline” is a retrospective comparator implemented in the evaluation harness, not a separately deployed conventional application. Likewise, successful interface generation means an HTTP 201 response with generated HTML; it does **not** prove that a real-world purchase, booking, or other external task completed.

## Final result and limits

The documented live evaluation reports that the keyword baseline ranked the relevant provider first for **2/4 fixed intents**, while the full agent path with blended retrieval did so for **4/4** and returned task-specific generated HTML for **4/4**. Because there is no agent lexical-only ablation, this comparison does not isolate the embedding contribution. A deterministic integration scenario showed a two-provider plan and interface. These are deliberately narrow, self-reported claims; raw live-run output is not checked in.

The prototype does not establish completed real-world outcomes, production safety, broad semantic-search quality, observed user-step reduction, or readiness for money, legal, medical, or other consequential effects. The modeled baseline and user-step metric are useful hypotheses, not user research.

## Reproduce

```bash
corepack enable
pnpm install
MODEL_MODE=mock pnpm --filter @agent-web/api eval
pnpm typecheck
pnpm test
pnpm build
```

The mock path is deterministic and uses no API credit. Reproducing the documented live numbers requires `MODEL_MODE=live` and an OpenRouter key and may vary as models and pricing change.
